> 目标：把 QBox 的 UI/UX 做到「成熟 TV 壳」水平 —— 焦点/滚动/边缘/一致性零硬伤，
> 视觉与交互对标 Netflix / Apple TV+（10-foot UI、焦点驱动、无鼠标）。
>
> 设备：`192.168.2.214:5555`（IP810N，Android 9，1920×1080，density 2.0，armeabi-v7a）
> 基线：`fongmi-561` @ 1.9.15（`575c3dd`）+ 1.9.16 未提交改动
> 验证：adb 逐键 + screencap + uiautomator + logcat（QBoxSnap / QBoxGrid / QBoxFocus）
>
> **这份文档是唯一台账**：历史问题、已修、回归项都记在这里；每轮先跑「回归清单」再测新项。

## 0. 术语与判定标准

| 缩写 | 含义 |
|---|---|
| FOCUS | 焦点：每个可交互控件必须有清晰焦点态；不允许焦点丢失/卡死/跳到屏幕外 |
| EDGE | 边缘：海报/标题/焦点环不得被裁掉、不得露出半截上一行 |
| JITTER | 抖动：焦点移动后内容不得「先冲过头再回弹」，横向移动时整排 y 不得变化 |
| CONSIST | 一致性：首页/分类页/搜索页/收藏页的行距、放大倍数、焦点描边、返回层级一致 |

## 1. 本轮（2026-11-03 第 1 轮）已定位并修复

### R1-01 分组标题被放大后的卡片压掉下半截（EDGE / P0）

- 现象：首页「更新推荐」标题只剩上半截，下半截被第一张海报的焦点环盖住；
  分类页/搜索页同结构同样存在。
- 根因：`CustomRowPresenter` 把分组标题塞进行内（1.9.16 改动），但给标题加的
  `LinearLayout.LayoutParams.bottomMargin = 18dp` 被 `ListRowView.addView(child, 0)`
  用自己的 LayoutParams 覆盖，实际 margin = 0；卡片聚焦放大 1.1×，顶边向上溢出
  约 5.5% 行高，正好压住标题。
- 修复：改为给标题 TextView 加 `paddingBottom = 18dp`（padding 不会被 LayoutParams 覆盖），
  让标题区高度真实包含聚焦放大的余量。`CustomRowPresenter.createTitle()`。
- 证据：修复后「更新推荐」四字完整，标题底与海报顶之间约 63px 空隙；焦点环不再碰标题。

### R1-02 列表到底时上一排「半截海报」永远挂在分类条下面（EDGE / P0）

- 现象：首页按到第 4/5 排时，屏幕上方一直露着上一排的半截海报 + 半行标题，
  像渲染错误；logcat 里 `QBoxSnap` 每 100ms 刷 `dy=227` 死循环（空转 smoothScrollBy）。
- 根因：列表底部没有滚动余量，最后一两排永远无法贴到内容区顶部；`requestSnap`
  发现 `dy>0` 就滚，但已经到底滚不动，`onScrollStateChanged(IDLE)` 又触发下一次，
  形成死循环。
- 修复：
  1. `CustomVerticalGridView.applyBottomPadding()`：`paddingBottom =
     height - paddingTop - rowHeight + rowSpacing`，保证任意一行都能贴顶；
  2. `snapOnce()` 对「同一个 dy 连续两次滚不动」直接放弃，打断空转；
  3. `computeClipTop()` 改按 `paddingTop - rowSpacing` 计算，压在「上一行底边」之上。
- 证据：首页 5 排逐排 DOWN，`rowTop` 全部 318、`dy=0`；最后一排完整、无残影、无空转日志。

### R1-03 换行时「先冲过头再滑回来」的弹簧感（JITTER / P0）

- 现象：按 ↓ 后内容先猛地上窜（实测行顶到 y=12/234），再被 snap 拉回 318，
  一秒钟内两次位移；向上移动更明显（回拉 340px）。
- 根因：1.9.16 用「滚动结束后 `smoothScrollBy` 补偏差」实现贴顶，和 Leanback 自己的
  布局/滚动抢控制权；且 Leanback 默认把「选中项的**中心**」作为对齐点，行顶永远对不准。
- 修复：交给 Leanback 原生对齐，删掉补位移这套逻辑的前提：
  - `setItemAlignmentOffset(0)` + `setItemAlignmentOffsetPercent(DISABLED)`：对齐点改为**上边缘**；
  - `setWindowAlignment(WINDOW_ALIGN_LOW_EDGE)` + `setWindowAlignmentOffset(paddingTop)`
    + `setWindowAlignmentOffsetPercent(DISABLED)`：选中行顶边精确落在内容区起点；
  - snap 保留为兜底（正常情况下 dy=0，不会触发滚动）。
- 证据：首页连续 ↓/↑，`QBoxSnap` 全部 `dy=0`，无二次滚动。

### R1-04 焦点守护每 500ms 打日志 + 可能抢焦点（FOCUS / P1）

- 现象：logcat 每 500ms 一条 `QBoxGrid guard ...`；理论上弹窗/面板打开时
  `getCurrentFocus()` 为空会把焦点抢回内容区。
- 修复：去掉日志；连续两次丢失焦点才接管（1s），窗口失焦时清零。
- 待验证：设置页弹窗、换源弹窗打开时是否还会被抢焦点（第 2 轮）。

### R1-05 详情页「线路」标签按 ↓ 永远下不到选集（FOCUS / P0）

- 现象：详情页焦点从播放器 ↓ 到线路标签后，再按 ↓ 完全没反应；选集、倒序、
  线路分页都到不了，遥控器像坏了。
- 根因：`FlagAdapter` 把线路标签的 `nextFocusDown` 设成 `R.id.episode` ——
  这是 `HorizontalGridView` 的 id，网格容器本身不可聚焦；`nextFocusDown` 指向
  不可聚焦的 View 时 FocusFinder 直接失败（不会回退到几何搜索），按键被吃掉。
  动作行 4 个按钮的 `nextFocusDown=@id/flag` 是同一个隐患。
- 修复：`VideoActivity.dispatchKeyEvent` 增加详情页纵向焦点路由
  `routeDetailFocus()`：播放器/动作行 → 线路 → 选集 → 倒序/分页 → 快捷行，
  `focusRow()` 递归取行内第一个可聚焦 item；反向逐级回退。
- 证据：真机 ↓ 三次焦点依次落 `FF有广` → `第01集` → `倒序`；↑ 反向可回。

### R1-06 搜索页历史首行按 ↑ 是焦点陷阱（FOCUS / P0）

- 现象：历史/热搜首行按 ↑ 没反应（热点区一行把按键吃掉、焦点不动），
  用户只能按返回退出搜索。
- 根因：`handleRecordKey` 对 UP 直接 `return isFirstRow(...)` —— 首行返回 true
  把按键消费掉，却没有把焦点交回搜索框。`handleWordKey` 早已支持，历史区漏了。
- 修复：首行 ↑ → `keyword.requestFocus()`；二行及以后交给默认焦点搜索上移。
- 证据：真机 历史第二行 ↑ → 第一行 ↑ → 搜索框（白描边 + 光标），再按字母可输入。

### R1-07 配置/UA/MPV 弹窗没有初始焦点 + 聚焦按钮白底白字（FOCUS / P0）

- 现象：设置页点「点播」弹出二维码配置窗，三个按钮（选择/确定/取消）没有任何
  焦点框，第一下 OK 不触发主操作；修复初始焦点后「确定」变成白药丸但文字也是白色，
  按钮直接看不见。
- 根因：`MaterialAlertDialog` 的布局没有 `requestFocus`；按钮 `textColor` 写死
  `@color/white`，而 `selector_button` 聚焦时背景是白药丸。
- 修复：三个弹窗（ConfigDialog / UaDialog / MpvConfDialog）在 `onStart` 里
  `post → positive.requestFocus()`；静态说明 `info` 改为不可聚焦（原来 focusable
  但没有焦点态，是第二个"按了没反应"的点）；按钮文字统一 `@color/text`
  （聚焦自动反色）。
- 证据：弹窗打开即「确定」白药丸 + 黑字；↓ 可到取消/选择。

### R1-08 播放控制条压在亮画面上不可读（CONSIST / P1）

- 现象：竖屏短剧的亮场景里，控制条标题与按钮白字压在白色床单上，几乎看不清。
- 根因：`shape_controller` 顶部 `#00000000` 起步，标题所在的上沿几乎是全透明。
- 修复：改为 `#7A000000 → #B8000000 → #E6000000`，标题行也有 48% 黑底。
- 待回归：真机截图对比（第 2 轮补）。

### R1-09 1.9.16 行容器把横向间距弄丢，卡片贴成一张（CONSIST / P1）

- 现象：首页「更新推荐」5 张海报彼此紧贴，没有 16dp 间距；分类页/搜索结果同样。
- 根因：`CustomRowPresenter` 重写后只保留了 `spacing` 字段，漏了
  `getGridView().setHorizontalSpacing(...)`。
- 修复：`createRowViewHolder` 里补上（必须 cast 成 `ListRowPresenter.ViewHolder`）。
- 证据：修后海报之间恢复 16dp 空隙，视觉呼吸感回来。

### R1-10 历史卡比海报宽 → 相邻两张卡的文字重叠（EDGE / P0）

- 现象：「最近观看」有两张历史卡时，第一张的片名压到第二张的片名上，
  看起来像一行乱码；卡片本身也互相压 17px。
- 根因：历史卡宽度由 `HistoryPresenter` 单独计算（比海报宽），而 1.9.16 又把行
  横向间距丢了；`name` 是 `match_parent`，卡片一宽文字就顶到下一张卡。
- 修复：`HistoryPresenter.onBindViewHolder` 把 image/name/remark/root 的宽度
  钉死为计算值；配合 R1-09 的间距，卡片不再互相压。
- 证据：修后两张历史卡间距 16dp，片名各自 ellipsize，无重叠。

### R1-11 分类页筛选面板与「逐行贴顶」互斥（FOCUS / P1）

- 现象：筛选面板展开后，从筛选行按 ↓ 进海报区时，整块筛选会被顶出屏幕
  （或焦点被拉回面板），两种行为都不对。
- 修复：`TypeFragment.showFilter()` 期间 `setSnapEnabled(false)` +
  `setRowsKeepVisible(true)`（FOCUS_SCROLL_ITEM，只在焦点行离开视口时滚动），
  收起时恢复贴顶；`CustomVerticalGridView.snapOnce` 去掉「上一行是标题」的
  旧启发式（1.9.16 标题已经画进行内，启发式会误把筛选行当标题）。
- 待回归：筛选展开 → 逐个 chip → 选一个 → 收起 → 焦点回第一排（第 2 轮）。

## 3. 回归清单（每轮必跑）

> 用 adb 逐键操作，每步截图 + 对照焦点框；不依赖 uiautomator 的 bounds 判断焦点
> （Leanback 列表上会返回旧坐标）。

### 3.1 首页

1. 冷启动：logo/loading 后首焦点落在第一张内容卡（有历史 → 历史卡）。
2. ↑ 到分类条（白药丸），再 ↑ 到源名（白药丸），再 ↑ 停住。
3. 分类条 → ←/→ 焦点移动，y 不变；OK 进分类页；↑ 回源名。
4. 源名 → 右移 5 次：搜索/直播/收藏/推送/设置依次展开成 icon+文字，时钟不跳。
5. 内容区 ↓×N：每排贴顶（rowTop=318），无上一排残影；到最后一排仍贴顶。
6. 内容区 ↑×N：逐排回退，最后回到第一排；再 ↑ 进分类条。
7. 海报行 ←/→：整排 y 不变（无上下抖）；最左/最右卡片完整可见。
8. 断网/空数据：不白屏、有提示。

### 3.2 分类页（VodActivity / TypeFragment）

1. 进页：tab 与首页同 y、同高；首焦点在第一排海报。
2. 筛选：展开 → 焦点落在第一排 chip；chip 横移 y 不变；点选刷新后焦点回该排；
   收起后焦点回网格第一排。
3. 换分类再回来：列表位置不被强制重置。
4. 滚到底自动翻页；翻页后焦点不丢。

### 3.3 搜索 / 聚合

1. 进页：首焦点在搜索框；↓ 进软键盘；输入有建议词；旧请求不覆盖新请求。
2. 热词首行 ↑ 回搜索框；麦克风只在 OK 时启动。
3. 聚合页：loading / 空结果 / 有结果三态；站点 tab 高亮当前页；↓ 进当前页网格。

### 3.4 设置 / 收藏 / 投屏 / 更新

1. 设置：每行可聚焦；二级页有返回；隐藏行后焦点不悬空；弹窗打开时焦点不被抢。
2. 收藏：首焦点第一项；删到空有 empty 态且焦点回退。
3. 投屏：进页有焦点，二维码可聚焦。
4. 更新：下载中可返回；禁用按钮不接收焦点。

### 3.5 详情 / 播放 / 直播

1. 详情：播放/简介/收藏/换源可聚焦；剧集行不溢出屏幕；倒序提示不遮半屏。
2. 播放：↑ 呼出控制条；进度条焦点 ←/→ seek；BACK 退出；控制条自动收起后第一下不误触；
   选完倍速/音轨/选集后控制条与焦点正确。
3. 直播：频道列表/信息条/控制条返回层级正确；加密分组可解锁。

## 6. 第 2 轮（间距 / 基础视觉，2026-11-03 晚）

用户反馈：**海报间隔等基础问题、不要元素重叠；各页面「离分类 tab 的距离 / 空白」要统一，不太空不太近。**

### R2-01 内容区起点统一：分类条下 32dp（P1）

- 之前：`qbox_content_top=144dp`，而实际列表 `paddingTop = 144 + zoomPad(≈15dp) = 159dp`，
  行顶距分类条 **41dp**；聚合页又是自己的 32dp inset。分类页没有分组标题时，
  分类条到第一张海报之间空一大条（实测 82px）；聚合页只有 35dp，两边不一致。
- 修复：`qbox_content_top` 改为 `135dp`（+ zoomPad ≈ 150dp），行顶距分类条 **32dp**；
  首页分组标题 / 分类页第一张海报都从 300px（1080p）开始。
- 证据（214 实测）：首页「最近观看」顶部 y=300（原 318）；
  分类页第一排海报 y=300；聚合页约 35dp，误差 ≤3dp。

### R2-02 历史卡与海报卡同一套网格（P0，含重叠）

- 历史卡与海报卡同为 332×（1080p）宽、16dp 横向间距；历史行 2 张卡
  `[64,411][396,711]`、`[428,411][760,711]`，与「更新推荐」列完全对齐，
  不再出现「第一张片名压到第二张片名」。
- 行距统一 24dp（`max(24dp, 7.5% 行高)`），分组标题与海报之间 18dp
  （标题的 padding-bottom，防聚焦放大压字）。

### R2-03 投屏页控件「能聚焦但看不出来」（P0）

- 之前：二维码和「推送剪贴板内容」虽然 focusable，但二维码没有焦点态
  （背景描边被不透明位图盖住）、剪贴板文字也没有焦点背景，用户完全看不出选中了谁。
- 修复：新增 `selector_qr_code`（聚焦 3dp 白框 + 常态 1dp 10% 白框），二维码加 8dp
  padding 让描边露出来；剪贴板改用 `selector_item`（聚焦白药丸）+ `@color/text` 反色。
- 证据：进页二维码白框，↓ 后剪贴板白药丸黑字。

## 7. 第 3 轮（焦点顺序 / 文案本地化 / 加载态 / 直播与设置回归）

### R3-01 详情页从播放器按右直接跳到「简介」，主操作「播放」被跳过（FOCUS / P1）

- 根因：`activity_video.xml` 里播放器 `nextFocusRight="@id/content"`（简介），
  而动作行顺序是 播放 / 简介 / 收藏 / 换源 —— 主操作被跳过，用户要按右再按左才能播放。
- 修复：播放器 `nextFocusRight="@id/play"`；同时删掉 5 处指向 `@id/flag` 的
  `nextFocusDown`（flag 是 HorizontalGridView、本身不可聚焦，是第二个隐藏焦点陷阱）。
- 证据（214）：播放器 → 右 = 播放（白药丸）→ 右 = 简介 → 收藏 → 换源；
  下 = 线路 `播放`（线路名）→ 下 = 选集 → 倒序。

### R3-02 播放错误提示是英文，混在纯中文界面里（CONSIST / P1）

- 现象：直播切线路失败时中央弹出 `Network Connection Failed`。
- 根因：`ExoErrorMessageProvider` 把所有 `PlaybackException` 映射成英文。
- 修复：按错误码全部改成中文（连接超时 / 网络连接失败 / 解码失败 / 版权授权…），
  未知错误统一「播放失败」。
- 待回归：下一次直播失败时确认真机显示中文（第 4 轮）。

### R3-03 页面加载态只有一个转圈，没有任何文案（N-04 / P1）

- 修复：`view_progress.xml` 增加「正在加载…」提示，由 `ProgressLayout` 打开
  （视频缓冲页仍只显示码率，不显示这句）；中英字符串都补了。
- 仍未解决：冷启动前 ~10s 是系统 Splash（只有 logo），因为配置加载在首帧前完成；
  要让用户看到「正在加载配置」需要把配置加载异步化/自定义启动页 → 记为 N-12。
