## 二、修复说明

### A1 / A3 筛选面板焦点（最关键）

三个断点，缺一不可：

1. **展开时**：`showFilter()` 里先压低内容起点 → 插入筛选行 → `postDelayed(280ms)` 调 `focusFirstFilter()`；
   `setSelectedPosition(0)` 之后如果 `requestFocus()` 失败，用 `firstFocusable()` 递归抓第一颗 chip 兜底。
2. **点选后**：`setClick()` 记录被点的行号（`mLastFilterRow`），`setAdapter()` 刷新完成后
   如果 `findFocus() == null` 就把焦点还回那一排。
3. **收起时**：`hideFilter()` 移除筛选行后焦点悬空，补一次「聚焦第一排海报」。

### A1 横向抖动

筛选项行从 `FOCUS_SCROLL_ALIGNED` 改回默认 `FOCUS_SCROLL_ITEM`。
ALIGNED 的语义是「每次聚焦都把 item 对齐到固定位置」，短列表里表现为整行内容左右位移；
ITEM 只在 item 不可见时才滚动，横移时行是静止的。

实测：`热度(x=64) → 最新(x=200) → 评分(x=336)`，三次的 y 恒为 282，行没有位移。

### A2 标题偶发不显示

`snapOnce()` 里判断「上一个 item 是不是矮行（高度 < 当前行一半）」，是的话把它当作当前行的分组标题，
一起对齐到内容区顶部。这样标题跟着行走，不会被贴顶顶出屏幕。

### A4 筛选与 tab 间距

筛选面板不是普通内容行，展开时用 `setContentTopTemp()` 把内容起点临时压到
「分类条下沿 + 8dp」（118dp + 8dp），收起时恢复 144dp 基线。
实测第一排 chip 顶距 tab 底从 26dp 降到约 18dp，视觉上贴住了分类条。

### A1 补充：横向切换整排上下抖（第五轮）

**现象**：横向切换海报时整排会上下移动一下，切换一次之后才稳定。

**根因**：贴顶校正自己把自己滚成了弹簧——
`snapOnce()` 用 `smoothScrollBy` 补正 → 平滑滚动结束发一次 `SCROLL_STATE_IDLE`
→ 又调 `requestSnap()` → `dy` 还有 1~2px 余量（横向切换会让行高产生亚像素变化）
→ 又滚一次。容差是 1px，等于每次都动作。

**修复**（三条纪律，缺一条就会抖）：

1. **容差 4px**：`|dy| <= 4` 直接返回，不吃横向切换的亚像素抖动；
2. **同一偏差只滚一次**：`dy == lastSnapDy` 直接返回，断掉「校正 → 滚动 → 再校正」的环；
3. **用 `scrollBy` 不用 `smoothScrollBy`**：瞬时位移不产生新的滚动状态回调，从源头断环。

**实测**：首页连续 → 四次焦点 `x=64/411/775/1139`，**y 恒为 281**；
聚合搜索页同样 `y 恒为 304`。整排不再上下移动。

### A2 补充：第一排默认焦点被裁（第五轮）

**现象**：首屏第一排的焦点卡顶部缺一条，动一下就好。

**根因**：`applyContentTop()` 里那次 `postDelayed(requestSnap, 240)` 跑在数据回来之前，
当时列表还是空的（holder 为 null，直接 return）；等数据到了，Leanback 按自己的规则摆放，
选中行顶部压在内容区起点上，放大溢出的 5% 就被切了。

**修复**：三个海报页（首页 `addVideo`、分类页 `addVideo`、聚合页）在数据落位后
各补一次 `App.post(requestSnap, 160)`。校正带 4px 容差且幂等，重复调用无副作用。

### A2 补充之二：裁剪线压在第一排焦点框上

**现象**：第一排焦点卡顶部的焦点框缺一条（`uiautomator` 实测焦点 top=281，裁剪线在 288）。

**根因**：裁剪线钉死在内容区起点（144dp=288px），但第一排聚焦放大后卡片顶部会向上溢出
约 23px（行高 5%），正好压在裁剪线上。

**修复**：裁剪线改为 `max(headerBottom, contentTop - zoomPad + 2)`，
即上提「一个放大余量」。行距（≥ 行高 7.5%）恒大于放大溢出（5.5%），
所以上提之后上一行的底边仍然落在裁剪线之上，不会露出来。

实测：裁剪线 259，第一排焦点 top=281 → 完整；上一行 bottom≈256 → 不可见。

## 三处海报展示的一致性对照

| 项 | 首页 | 分类页（tab） | 聚合搜索页 |
|---|---|---|---|
| 行高来源 | `Product.getSpec(style)[1] + 52dp` | 同左 | `Product.getSpec(rect)[1] + 52dp` |
| 行内间距 | 16dp | 16dp | 16dp |
| 行间距 | `max(24dp, 行高×7.5%)` | 同左 | 同左 |
| 内容区起点 | `144dp + 放大余量` | 同左 | `32dp + 放大余量`（页头在 LinearLayout 里占位，结构不同） |
| 放大 | 1.1×（`ZOOM_FACTOR_SMALL`） | 1.1× | 1.1× |
| 焦点描边 | `selector_vod` | 同左 | 同左 |
| 裁剪线 | `contentTop - zoomPad + 2`（≈259px） | 同左 | 自身顶部 - zoomPad + 2 |
| 贴顶校正 | 有 | 有 | 有（沿用自身 paddingTop） |
| 分组标题 | 有（最近观看/更新推荐） | 无 | 无 |

唯一无法统一的是「内容区起点」和「分组标题」——两者由页面结构决定
（首页/分类页是浮层页头，聚合页是 LinearLayout 页头），强行拉平反而会把
聚合页的海报压到站点 tab 上。放大倍数、间距、焦点视觉、点击行为已经全部一致。

### B1 滚动动画

裁剪线**固定**在内容区顶边，不再跟着选中行跳；上一行由 Leanback 正常滚动送出去，
滚动停下后用 `smoothScrollBy` 补正（通常只差几十像素，看着是动画多走一段）。

### B2 聚合搜索页

接入 `applyContentTopKeepPadding()`：沿用页面自己的 32dp paddingTop，
只补行距、放大余量和贴顶。

### B3 筛选行豁免贴顶

`setSnapStartIndex(筛选行数)`：位置小于该值的行不做贴顶校正，
筛选行逐行下移只滚一小段，多行始终可见；进入海报行才贴顶。

### B5 / B6 放大与裁剪

- 首页三行 presenter 全部改 `ZOOM_FACTOR_SMALL`，与分类页/聚合页一致；
- 裁剪线位置 = 行顶边 − 放大溢出（行高 5.5%），正好落在「放大后卡片的上边缘」；
- 不变式：行距 = max(24dp, 行高 7.5%) > 放大溢出 5.5%，所以让开后上一行仍整行不可见。

## 四、已知未处理（记录，不在本轮范围）

1. **详情页有一次巨型提示块**：`Notify` 显示倒序播放提示时，如果文案很长会撑成大黑块遮住半个屏幕（实测出现「首度聚焦破碎友情…」两段）。建议给 `Notify.makeText` 限制最大宽度/行数。
2. **播放页控制条 14 个按钮**：720p 下已接近屏幕边缘，文案再长会挤出去。
3. **空态/错误态**各页面自行绘制，文案与样式不统一。
4. **启动加载 10~20 秒**只有 logo + 小转圈，缺「正在加载配置」文案。
